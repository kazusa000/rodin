# KelvinBall: native solver + BEM

The internship workspace's fixed Carlos reference and three research branches
are defined in [WORKSPACE_BRANCHES.md](docs/WORKSPACE_BRANCHES.md).
The active local integration entry is `codex/p03-bem-coupled`; the historical
`codex/clement-swift-bem` source is retained under the historical archive reference.

This example contains the native Carlos solver, MMG/SWIFT reconstruction,
the BEM/CUDA operator, actual-BEM acceptance and saved-result viewers.
Everything is bundled in this Rodin checkout, originally integrated on
`codex/clement-swift-bem`; no Project03 checkout is needed.

## Start here

Read [BEM_WORKFLOW.md](BEM_WORKFLOW.md) for installation, deployment and
copyable commands. The single entry point is:

```sh
python examples/ShapeOptimization/KelvinBall/scripts/kelvin-bem.py --help
```

| Command | Purpose |
| --- | --- |
| `native` | Build/check the solver, generate an initial mesh, or propose one update |
| `bem` | Measure a mesh and export its six BEM outer-boundary velocity traces |
| `compare` | Compare **one** BEM-accepted MMG/SWIFT update from the same mesh |
| `viewer` | Create a rotating, iteration-slider viewer from saved histories |
| `build-cuda`, `baseline` | Setup and original-Carlos baseline checks |
| `diagnostics` | Geometry, reconstruction audit, saved-field exports, scans and plots |

`compare` is a bounded backend-validation campaign, not a long optimization
loop. The available update stages and their acceptance conditions are documented
explicitly; this cleanup does not add an optimizer or change the numerical method.

## Code map

- Native `*.cpp/*.h`: FEM states/direction, volume null space, level-set
  transport, soft thickness, MMG/SWIFT and pressure gauges.
- `python/kelvin_bem/native_worker.py`, `bem_worker.py`,
  `compare_backends.py`: the executable workflow stages.
- `bem_solver.py`, `bem_boundary.py`, `cuda_operator.py`: one BEM solver
  implementation, outer-wall traces and optional GPU operator.
- `acceptance.py`, `periodic_geometry.py`, `solid_connectivity.py`:
  merit and geometry/connectivity checks.
- `history_viewer.py`, `render_shape.py`, `plot_history.py`: post-processing.
- `tests/`: numerical, IO, CLI and package regressions.
- `reproduction/`: fixed numerical preset, deployment example and provenance.

Keep builds, meshes generated by runs, fields, logs and HTML viewers **outside**
the source checkout. Old experiment data is retained, not copied into this example.

## Method and traceability

- [Carlos native method](docs/CARLOS_METHOD.md): original mathematical and native-solver documentation.
- [Migration validation](MIGRATION_VALIDATION.md): the completed single-checkout validation.
- [Cleanup record](docs/SOURCE_CLEANUP.md): renamed modules, deleted unused code and compatibility.

The workflow remains cubic O24 with BEM measurement/acceptance, a FEM proxy
direction and soft `rho-P` thickness. Original-panel exports with open seams
remain BEM diagnostics, not closed-body or printing acceptance.
